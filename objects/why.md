# Explicit was always better. Now it's also cheaper. Tomorrow, it's what everything runs on.

Making things explicit was always the right way to work ("Explicit is better than implicit", the
Zen of Python). But the cost fell on humans: writing, keeping up to date, linking. Documents died,
and the semantic web failed because humans had to write the links.

Agents move the cost: intelligence writes, links and keeps up to date. Explicit becomes the
cheapest path. And since each explicit object makes the next turn easier, it compounds, at no
extra human cost.

Tomorrow, whatever executes, software agents now and robots later, runs on what people want. A
more capable executor makes the source worth more, not less: it is what the executor runs. The
stake is small and the gain grows with the machines, so having a source is a bet that does not
lose, as long as making it explicit stays cheap (the first hypothesis below).

## The simple idea

**Your intent is the source. Intelligence runs it.**

| Part | Here |
|---|---|
| the source | intent: what you want, decide and know, made explicit as objects |
| the engine | intelligence: any agent |
| the fuel | compute: tokens, which run on electricity |

Without a source, the engine still runs, and it produces the generic. Each time the executor got
more capable, the source moved closer to the human: instructions for the processor, then languages
closer to thought, then declarative code that says what, not how (SQL, infrastructure as code).
Intelligence understands intent, so the source can be the intent itself.

Make it explicit once, and everyone benefits: a model of the standard library, written once,
serves everyone who has a use for it.

You don't do more. You do less, and get more.
